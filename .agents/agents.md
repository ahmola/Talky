# 에이전트 기본 준수 사항

프로젝트의 수행 주체로써, 에이전트가 지켜야 할 기본 규칙을 정의한다.

대전제이므로, 대부분의 상황에서는 지키도록 하나, 상황에 따라서 무시하는 것 가능하다.

그러한 상황은 에이전트가 판단하기에 성능을 저하시키거나 코드 응집도를 높이는 등의 코드 및 UX를 저하시키는 상황을 말한다.

이외에 구체적인 서비스 구현 플랜은 **.agents** 디렉터리 내에 있는 하위 디렉터리 내의 **skills.md**를 참조한다.

**.agents** 디렉터리에 있는 하위 디렉터리들의 이름이 구현할 서비스의 이름이다.

## 기본 규칙

1. SOLID 원칙, 클린 코드, 디자인 패턴을 준수하도록 한다.

2. 서비스 단위로 디렉터리를 만들며, 각 서비스에서는 각 언어 및 프레임워크에서 통용되는 디렉터리 구조를 따른다.

3. 각 서비스의 루트 디렉터리에는 Dockerfile이 정의되며, 프로젝트 최종 루트에는 docker-compose를 작성하여 전체 서비스를 한꺼번에 실행 가능하도록 한다. 만약 서비스에 여러 하위 서비스들이 있다면, 서비스의 루트 디렉터리에 Dockerfile이 아닌 docker-compose를 작성하여 서비스 단위로 테스트 가능하도록 한다.

4. 각 서비스 디렉터리에는 README.md를 작성하여 무슨 기능을 어떻게 구현했는지 상세하게 설명한다.

5. 테스트 코드를 각 언어 및 프레임워크에 맞게 작성하며 무엇을 테스트하는지 적는다. 테스트는 일반 코드베이스를 테스트하는 단위 테스트에서부터 통합 테스트, 부하 테스트를 진행한다. 부하테스트의 경우 Grafana K6를 사용하는 테스트 시나리오를 typescript/javascript(둘 중 더 빠르고 효율적인 것을 유연하게 선택)로 작성한다.

6. 실행이 불가하거나 무언가 꼬여서 너무 코드 문맥이 복잡해졌다고 판단된다면, **.agents**를 제외한 모든 디렉터리 및 그 하위 디렉터리와 파일들을 전부 삭제 후 처음부터 다시 시작한다. 이 때, 삭제를 하기 전에 꼭 허락을 받도록 한다.
